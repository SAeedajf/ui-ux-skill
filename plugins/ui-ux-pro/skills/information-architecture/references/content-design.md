# Content design and UX writing

Use this reference when page structure, interface text, content format, or content lifecycle affects a user's task.

## Decision sequence

1. Identify the user need and the decision or task the content must support.
2. Inventory the content and its current owner, location, format, and maintenance need before adding more.
3. Choose the amount and format of information that supports the task; prefer plain, specific wording and accessible structure, but validate against the audience, language, and domain.
4. For interface copy, coordinate content structure with field labels, instructions, validation messages, status messages, and recovery actions. Check that each message explains what happened and what the user can do next.
5. Plan review, ownership, and retirement for content that can become inaccurate.

S125, the GOV.UK content-design guide, supports user-need-led planning, format/quantity decisions, accessibility, plain English, and content maintenance in a UK public-service publishing context. It is not evidence that its wording, governance, or service conventions fit every product. Do not copy source prose; for Persian and mixed-direction interfaces, use the repository's Persian/RTL Skill and validate the actual localized strings.

For specific error-message implementation, route to the `forms-input` Skill and its S129 guidance. For research-method selection, route to `ux-discovery`. Each portable Skill package contains its own local references, so these are cross-Skill routing cues rather than local file links.
