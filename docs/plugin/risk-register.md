# UI/UX Pro plugin risk register

**Reviewed:** 2026-10-14. Ratings are initial design assessments, to be updated with implementation evidence.

| ID | Risk | Impact / likelihood | Prevention | Verification gate |
| --- | --- | --- | --- | --- |
| R1 | Portable format is mistaken for universal host support | Users cannot discover, install, or activate the package on a promised surface | Publish a per-host matrix; distinguish package conformance from host behavior; avoid blanket “works everywhere” claims | Test each named host/version through discovery, install, fresh-session discovery, and invocation |
| R2 | Existing user-level/project Skills and the Plugin load the same capability twice | Duplicate routing, extra context, or conflicting instructions | Preserve current Skill IDs; document one active installation path; recommend removing/disable duplicate copies where the host supports it; don't rename 15 Skills without evidence | Compare installed Skill inventory before/after; test prompt routing with duplicate and single-source configurations |
| R3 | All 15 Skills load for every UI task | Unnecessary context and less accurate routing | Keep one primary router; load one primary Skill and only actual handoff Skills; use progressive disclosure for references; do not put all reference text in plugin-level instructions | Inspect fresh-session traces for representative positive/negative tasks; record Skills and references actually read |
| R4 | Generated bundle drifts from `.agents/skills/` | The installable package differs from reviewed canonical source | Build package from canonical paths; CI regenerates and byte-compares; generated files clearly labelled; prohibit manual edits in bundle | Clean-checkout reproducibility test and exact file/hash comparison |
| R5 | Relative reference links break after packaging | Skills lose necessary local methods/checklists | Preserve per-Skill directory structure; validate local Markdown links and referenced assets; reject escaping/symlink paths | Build from clean checkout, install in disposable host location, validate all local links from package root |
| R6 | Plugin and Skill versions diverge | Users receive an incoherent release | One package semantic version in one metadata input; don't assign independent Skill versions; release manifest binds version to source commit and hashes | Build/version assertion; release manifest audit against Git tag/commit |
| R7 | Codex compatibility manifest conflicts with portable manifest | Host-specific override silently changes package identity or behavior | Omit overlay until an observed requirement; if added, generate from one metadata input and document precedence | Test portable-only and overlay package against current target client; compare effective identity/component set |
| R8 | Existing CLI config prevents marketplace commands | Host smoke test cannot reach the package | Keep environment issue separate from package result; use a disposable CLI home for later test or repair only through user's normal config process | Record exact CLI/config error; rerun in isolated supported environment without exporting credentials |
| R9 | Public/OpenAI directory path is confused with a GitHub marketplace | Users expect a GitHub repo link to publish a universal listing | Document repo marketplace as source/testing/team distribution; document ZIP upload, account eligibility, review and publish as separate public-directory flow | Submission checklist and a reviewed draft, only when explicitly in scope |
| R10 | ChatGPT web, desktop, workspace, and mobile are treated as one surface | Unsupported install claims, especially mobile | Keep surfaces separate in docs; use UNVERIFIED where no evidence exists; check plan/workspace/admin requirements | Surface-specific current documentation and target-client evidence |
| R11 | Third-party source text/assets are redistributed under repository CC BY | Copyright/license violation or misleading license attribution | Keep source links and brief factual notes; retain attribution; do not copy proprietary articles, paid research, logos, screenshots, or assets; audit source licenses before bundling | File-level license/provenance scan and human review before public ZIP |
| R12 | Secret or developer-local state enters the package | Credential exposure or non-reproducible build | Build allowlist from source directories; deny `.env`, tokens, home paths, local cache, debug traces, and credentials; package from clean checkout | Secret scan; inspect ZIP entries; build in clean CI |
| R13 | Build/test depends on a hosted service, paid model, or OS-specific tool | Cost, flakiness, or contributor setup burden | Use Python standard library and deterministic checks; keep LLM evals separate and explicitly optional; do not ship an MCP server | Build on Linux/macOS/Windows where feasible; deterministic CI with network disabled |
| R14 | Old clients reject a newer manifest/schema or silently ignore components | Installation fails or incomplete Skills appear | Pin the published schema version; publish minimum tested host versions only after evidence; include compatibility fallback only on demonstrated need | Schema validator plus package smoke test on minimum/current supported host versions |
| R15 | Package path or GitHub marketplace sparse checkout omits Skills | Catalog is visible but install cannot resolve components | Keep full package under one `plugins/ui-ux-pro/` root; document required sparse paths; validate package containment | Clone/sparse-checkout and package install from a fresh repository snapshot |
| R16 | Codex usage limits are assumed bypassed by packaging | Misleading product claims and unexpected quota exhaustion | Say the plugin is local instructions/resources; make no model, account, quota, or usage-limit guarantee | Review listing/README copy for quota and model claims |

## Open evidence gaps

- Local plugin install and activation have not been tested in Codex desktop or ChatGPT desktop.
- The installed Codex CLI's marketplace commands cannot currently read this account's existing config; see the compatibility matrix.
- ChatGPT mobile plugin support remains unverified.
- Public listing requirements and developer eligibility have not been checked in a signed-in submission portal.
- Six source references remain partially verified; preserve their exact status and scope in any derived guidance.
- The current activation ledger includes `BLOCKED` and `NEEDS_REVIEW` cases; none should be upgraded to PASS by package build success.
